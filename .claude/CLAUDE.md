# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Teleport (Zero-Cloud LAN Teleport) is a desktop app, written in Python 3.12+, for sending very large files and syncing the clipboard between computers on the same LAN. There is no cloud, no accounts and no telemetry. It is built as a release-quality product. Phase 1, discovery and pairing, is done (N1 measured on a bridged VM, `docs/benchmark.md`); next is phase 2, file transfer. Done so far: framing, device identity, TLS 1.3 + mTLS, the control-connection messages (`control_open`, `ping`, `pong`), the offline pairing foundation (`hello`/`pair_*` messages, the 6-digit code with the responder's nonce commitment, the trust store), the sans-IO pairing state machine with its anti-spam gate (`core/pairing.py`), the node lock, mDNS discovery (`core/discovery.py` + `net/discovery.py`), and the one-port connection layer (`net/connection.py`: listener, `hello` exchange, connection kinds, limits, keepalive via `core/keepalive.py`, the connection-kind table in `core/messages.py`), the app layer's pairing service and node (`app/pairing.py`, `app/node.py`, `app/settings.py`, `app/devices.py`), the shared `atomic.py`, the control-link state machine (`core/links.py`: §6.1 dedup, §6.2 reconnect/blocking), mDNS and self-maintained control connections inside the node, and CLI `identity` / `list` / `listen` / `pair <name | id prefix | ip[:port]>` / `unpair`. Not written yet: transfer, resume, clipboard, the UI and the CLI↔node IPC. The N1 benchmark scripts live outside the repo, in a `n1-bench` folder next to it.

The parent folder of `.claude/` is the git repo root (`git@github.com:Nha-Cong-Dong/zero-cloud-lan-teleport.git`, public). The repo root holds only `README.md`, `LICENSE` and `pyproject.toml`. Every other Markdown doc lives in `docs/`. Keep the root that tidy.

`docs/README.md` is the index. It says which doc owns which information, and holds the glossary and writing conventions. The product and planning docs, read in this order:
- `docs/y_tuong.md`: the why. Pain points, core values, target experience, **product principles** (use them to settle trade-offs) and the post-v1.0 vision.
- `docs/mvp.md`: the what. Scope, features F1–F12 with acceptance criteria, non-functional requirements N1–N12 (the only source of quality numbers), error messages, release criteria.
- `docs/ke_hoach.md`: the how and when. Technical design, roadmap and **current phase status**, testing, technical risks, open decisions.

The technical docs are `architecture.md` (layers, process model, **module status**), `protocol.md` (wire format), `CONTRIBUTING.md`, `SECURITY.md` and `CHANGELOG.md`.

Each fact is written in full in exactly one doc; other docs refer to it by code (`mvp N4`, `ke_hoach mục 3.4`) instead of copying numbers or text. When docs disagree, `protocol.md` and `architecture.md` win on the wire format and module status, `mvp.md` wins on requirements, `ke_hoach.md` on design and schedule. When a phase finishes, update its status in `ke_hoach.md` §5.1 as well as `architecture.md`.

## Commands

Run from this folder on Windows/PowerShell. The venv lives at `.venv/`.

```powershell
python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"                          # cryptography, zeroconf, ifaddr + pytest, pytest-asyncio, hypothesis, ruff
pytest                                           # all tests
pytest -m "not integration"                      # skip tests that open real sockets on 127.0.0.1
pytest tests/net/test_tls.py::test_verify_fingerprint_accepts_equal   # single test
ruff check . ; ruff format --check .             # CI runs exactly: ruff check, ruff format --check, pytest
teleport identity                                # CLI entry point (also: python -m teleport)
teleport listen                                  # wait for pairing (shows the 6-digit code, asks [c/k])
teleport pair 192.168.1.5                        # pair with a machine by IP (ip or ip:port)
teleport list                                    # devices seen via mDNS for a few seconds (no node.lock, no advertising)
teleport pair PC-Nha                             # pair by name or device_id prefix as `teleport list` shows it
```

CI (`.github/workflows/ci.yml`) runs on Windows, macOS and Linux with Python 3.12 and 3.14. pytest uses `asyncio_mode = "auto"` (a plain `async def test_...` works) and `--import-mode=importlib`. Tests mirror the layers (`tests/core/`, `tests/trust/`, `tests/net/`, `tests/app/`), and socket tests carry `@pytest.mark.integration`.

The distribution name is `zero-cloud-lan-teleport` and the import name is `teleport`. The version has one source, `__version__` in `src/teleport/__init__.py`; `pyproject.toml` reads it dynamically. Set `TELEPORT_HOME` (or pass `--config-dir`) to give each node its own identity when running several nodes on one machine.

## Architecture

Layering: `core ← trust ← net ← app ← ui / cli`. `tests/test_architecture.py` parses every import, relative ones included, and enforces these rules:
- A layer imports only the layers below it. `ui` and `cli` never import each other.
- `core` is **sans-IO**. It must not import `asyncio`, `socket`, `ssl`, `threading`, `zeroconf`, `ifaddr`, `PySide6`, `teleport.paths`, `teleport.lock` or any other layer.
- Every top-level `teleport.*` module belongs to a layer or is a shared utility in `SHARED` (`paths`, `lock`, `atomic`). A new package must be added to `LAYERS` (or `SHARED`) in that test and to `docs/architecture.md`.

`paths.py`, `lock.py` and `atomic.py` are shared utilities that any layer except `core` may use. `atomic.write_atomic(path, content)` writes `<path>.tmp` → fsync → `os.replace` (retries on `PermissionError`) and raises `OSError` unchanged; callers wrap it (`TrustStore` → `TrustStoreError`). `lock.py`: `NodeLock(config_dir, name="node.lock")` is an OS file lock (`msvcrt` on Windows, `flock` on POSIX), giving one node per config dir; `trust.identity` also uses it as `identity.lock` while creating an identity. Windows releases a killed process's lock asynchronously, so use `acquire(timeout=...)` wherever the holder may have just died (e.g. node start after a crash). `paths.TRUSTED_FILE` is the one name for `trusted.json`. `docs/architecture.md` is the **single source** for module status and the process model. `docs/protocol.md` is the wire spec (protocol v1, draft), and any wire-format change must update it in the same PR. Create a module only when there is real code for it; don't add empty placeholder files.

What lives where:
- **core**: pure functions and state machines. `framing.py` encodes and decodes control frames: `[uint32 BE length][UTF-8 JSON object]`, capped at 16 MiB (`MAX_MESSAGE_SIZE`), or 16 KiB on unauthenticated pairing connections (`MAX_PAIRING_MESSAGE_SIZE`).
  - `messages.py` holds frozen dataclasses for each message type. Validation runs in `__post_init__`, and `parse_message` and `to_dict` sit on top. This is the single place where untrusted peer fields are checked, using ASCII-only `re.fullmatch` checks (`pair_nonce.signature` is exactly 128 lowercase hex, its length taken from `core.pairing_code`). It also holds the connection-kind table: `ConnectionKind`, `allowed_types(kind)`, `opening_kind(msg, has_client_cert=...)` (`pair_request` only without a client cert, `control_open` only with one) and `check_message_kind` (`WrongConnectionKind`, a `MessageError`).
  - `keepalive.py`: `Keepalive(now, ping_interval=10, dead_after=30)` is a sans-IO timer (`sent`/`received`/`poll`/`next_wakeup`). It counts **bytes**, not messages: any read, even part of a frame, counts as received; any send (pongs included) counts as sent. `DEAD` is sticky.
  - `pairing_code.py`: `make_commitment(fp_responder, n_B)` / `check_commitment(fp_responder, n_B, commitment)` for the responder's nonce commitment, `pairing_code(fp_initiator, fp_responder, n_A, n_B)` for the 6-digit code from both fingerprints and both nonces, `format_code`, and `proof_payload(fp_initiator, fp_responder, n_A, commitment)` (155 bytes, signed by the initiator; `PROOF_SIGNATURE_SIZE = 64`) (`docs/protocol.md` §5.2). Nonce generation lives in `app`, not here.
  - `display.py`: `display_name(name, *, max_width=DISPLAY_NAME_WIDTH)` renders a peer-chosen (unauthenticated) name: blank-looking characters (Zs other than U+0020, U+2800, U+3164, U+115F/1160, U+FFA0) become `·`, width is counted in terminal columns and long names are cut with `…`. mvp §7.2 owns the width and the prompt layout: the code is always printed before any peer-chosen text.
  - `pairing.py` is the pairing flow as a sans-IO state machine: `InitiatorSession` / `ResponderSession` take events (`Start`, `MessageReceived`, `BadMessage`, `UserDecision`, `Tick`, `ConnectionLost`, `Cancel`) plus a monotonic `now` and return actions (`SendMessage`, `ShowCode`, `SavePeer`, `Close`). The responder commits first: `pair_request{cert}` → `pair_commit` → `pair_nonce{nonce, signature}` → the responder returns `[ShowCode, SendMessage(pair_reveal)]` in one batch, so n_B never leaves before its code is shown; the initiator shows its code only after `check_commitment` passes (`docs/protocol.md` §5.1 invariants). Proof of possession: the initiator signs `pairing_code.proof_payload(fp_A, fp_B, n_A, commitment)` through the required `sign_proof` callable (called before any state change; a result that is not 64 bytes raises `PairingUsageError`), and the responder checks it through the required `verify_proof` callable **before** `ShowCode` (only `is True` counts; otherwise `pair_abort{invalid}` + `PROTOCOL_ERROR`, no code, no `pair_reveal`). `core` never touches keys: `app` passes in `trust` functions. `SavePeer(peer, name)` is emitted only after this side has sent **and** received `pair_confirm`; both roles update the stored name on a re-pair. `PairingGate` holds the anti-spam rules (one session at a time, per-IP backoff, tie-break when both sides initiate, and a cap on codes shown as responder per sliding window via `code_shown`, mvp F3). The peer cert is parsed in `app` (via `trust`) and passed in as `DeviceCert`; `app/pairing.py` generates nonces and wires the session to a connection.
  - `discovery.py` builds and validates mDNS records (TXT, addresses, virtual-NIC filtering) and holds `DiscoveryTracker`, a sans-IO state machine fed zeroconf's Added/Removed plus resolve results and a monotonic `now`; it returns device events and resolve/probe requests (liveness probes, slower backoff for vanished devices). Paired devices (`set_priority`) are always tracked and don't count toward the 256 limit; services seen while full go to a FIFO overflow list (≤ 1024) and are admitted when a slot frees (`docs/protocol.md` §8). `NetworkWatch` gets periodic samples (advertised addresses, monotonic and wall clock) and returns `ADDRESSES` (restart mDNS) or `WOKE` (clock jumped > 15 s: re-advertise).
  - `links.py`: `LinkTracker` keeps control connections to trusted devices (events in: `trusted_changed`, `device_seen`/`device_gone`, `network_changed`, `retry_now`, `connect_finished`, `incoming_control`, `connection_lost`, `tick`, plus a non-decreasing `now`; actions out: `Connect`, `CancelConnect`, `CloseConnection`, `Notify(LinkUp|LinkDown|LinkFailed)`). Rules (`docs/protocol.md` §6.1/§6.2): at most one connection per device; the new one wins if the old is ≥ 5 s old or both were opened by the same side, otherwise the one opened by the smaller `device_id`; retry 1, 2, 4… ≤ 30 s; `Rejected`/`IdentityMismatch`/`VersionMismatch` block scheduled retries (only mDNS events or the user retry, still on that schedule); event-driven retries are ≥ 2 s apart; each failure kind is reported once (unreachable only after 3 in a row). mDNS loss never closes a live connection.
  - Transfer and resume logic goes here as sans-IO state machines: events in, actions out. That keeps the hard logic testable with hypothesis and no sockets.
  - Transfer logic does **not** belong in `net`.
- **trust**: `identity.py` holds the device's ECDSA P-256 key and self-signed cert. The fingerprint is the SHA-256 of the DER cert, and the device id is the CN without its `teleport-` prefix.
  - `load_or_create_identity` creates an identity only when both files are missing and `trusted.json` holds no devices, while holding `identity.lock`. The cert is valid 2000-01-01 to 9999-12-31, so no date depends on the local clock. A half-missing, corrupt or mismatched identity raises `IdentityError` and is never regenerated, because a new identity silently drops every pairing. The CLI prints the message and exits 1.
  - `peer_cert_from_pem` and `peer_cert_from_der` strictly validate a peer's cert, because every trusted cert becomes an mTLS trust anchor. Anything that could act as a CA is rejected. Any exception raised while parsing or checking the cert becomes `InvalidCertificate` (`cryptography` raises classes such as `UnsupportedGeneralNameType` that derive straight from `Exception`).
  - `store.py` is the `TrustStore` for `trusted.json`. Writes are atomic, and a corrupt file raises `TrustStoreError` and is never rewritten. Build it with `TrustStore.load()` only.
  - Pairing exchanges and stores the peer's cert PEM (`Identity.cert_pem()`).
  - Pairing signatures: `load_pairing_signer(identity)` returns a `PairingSigner` (`sign(payload)` → 64-byte r‖s, IEEE P1363; `repr` hides the key) and raises `IdentityError` if the key does not match the cert. `verify_pairing_proof(peer, payload, signature)` never raises; anything wrong returns False. Every signature made with the identity key starts with its own `teleport-…-vN` label (`docs/protocol.md` §1).
- **net**: only I/O, no business decisions.
  - `stream.py` reads and writes frames on asyncio streams. `read_message` returns `None` on a clean EOF at a frame boundary.
  - `discovery.py`: `MdnsDiscovery` wraps zeroconf (advertise/update/goodbye, browse, resolve what the tracker asks for, read NICs via ifaddr). It makes no decisions; mDNS results are hints only, identity is trusted solely via the TLS fingerprint.
  - `tls.py`: the client checks the **full** server fingerprint against the stored one (`CERT_NONE` + `verify_fingerprint`); there is no prefix/short-pin verification.
  - `server_context(identity, trusted_certs, allow_anonymous=True)` sets `CERT_OPTIONAL`, disables session tickets (`num_tickets = 0`, so an unpaired peer cannot resume an old session) and loads the trusted certs as anchors: a client sending an unknown cert fails the handshake (even with an empty list), a client sending no cert gets an anonymous connection that may only pair. Verified in `tests/net/test_tls.py`.
  - `connection.py`: a node listens on **one port** (default 47474). `Listener` accepts **plain TCP** and calls `StreamWriter.start_tls` per connection with the **current** context, so `update_trusted` swaps the context without reopening the port (never `sni_callback`). `start_tls` must stay the first real `await` of the handler (otherwise the ClientHello can land in the old `StreamReader` buffer and the handshake hangs on Python < 3.14). `control_open` re-checks `is_trusted(fp)` because the handshake may have used an old context, with no `await` between that check and `on_connection`.
  - Connection kinds on that port (`docs/protocol.md` §2): the client's first message after `hello` declares it: `pair_request` (no client cert), `control_open` or `data_open` (trusted client cert; `data_open` arrives in phase 2). Data connections are opened in the same direction as the current control connection.
  - Limits (`docs/protocol.md` §2.3): connections still opening (TCP → kind known) max 4 per IP / 64 total, aborted before TLS; anonymous ones max 1 per IP / 8 total, aborted right after the handshake; the whole TLS + `hello` + opening chain has one 10 s deadline that is never extended; `hello` and the opening message are read with the 16 KiB cap. Rejections are `transport.abort()`, never a graceful close. Every counter is released exactly once on every exit path. The timeout/limit constants are module globals read at use time, so tests `monkeypatch.setattr` them.
  - `Connection.send` writes 64 KiB chunks, each `drain()` bounded by `DRAIN_TIMEOUT` (30 s); `close()` is bounded by `CLOSE_TIMEOUT` then aborts. `ControlChannel.run` drives a control connection (auto-`pong`, `ping` from `core.keepalive`) and returns a `CloseReason`.
  - Under TLS 1.3 a rejected client still sees the connect succeed and only fails on its first read. So a connection counts as established only after the server's `hello` has been read. `open_pairing` / `open_control` try every address in parallel; errors before the TLS handshake completes are `Unreachable`, EOF/reset after it but before `hello` is `Rejected`, plus `IdentityMismatch` and `VersionMismatch` (`most_relevant_error` picks what to show).
- **app**: the only orchestration layer, shared by the CLI and the UI. It returns outcome codes; user-facing wording lives in `cli.py` (and later the UI).
  - `node.py`: `Node(config_dir, *, name, port, host, accept_pairing, on_pairing_prompt, on_pairing_finished, mdns=None, auto_connect=True, on_event=None)` holds `node.lock` from `start()` to `close()`, loads identity and trust store, and opens the `Listener` (47474 or the port saved in `settings.json`; any `OSError` there falls back to port 0 and saves it; an explicit `port=` is used as is, never saved). It routes pairing connections to `PairingService`; every control connection (incoming or outgoing) is registered with `core.links.LinkTracker` before any `await` and the node only executes the tracker's actions. `mdns=MdnsOptions(...)` turns on mDNS (best effort: errors go to `discovery_error`, never fail `start`); with `advertise` it re-reads addresses and clocks every 5 s (`NetworkWatch`). `auto_connect` feeds mDNS sightings to the tracker so the node opens and keeps control connections itself (always with the stored fingerprint). `on_event` receives `NodeEvent`s (`DeviceOnline`/`Offline`/`Connected`/`Disconnected`, `ConnectFailed`); `devices()` returns `DeviceView`s. `MdnsDiscovery` and `open_control` are called through `teleport.app.node` globals so tests can swap them. `unpair(device_id)` is synchronous from `store.remove` through `update_trusted` to taking the connection out of the table, then closes it. If `close()` is cancelled, `PairingService.abort_all()` runs before the lock is released (no `trusted.json` write afterwards). `scan_devices(config_dir, timeout=3)` is `teleport list`: browse only, no `node.lock`, no advertising. `unpair_offline(config_dir, query)` is the CLI's unpair when no node runs (holds `node.lock`). `accept_pairing=True` without `on_pairing_prompt` raises `ValueError`.
  - `pairing.py`: `PairingService` drives `core.pairing` sessions over a `Connection` (at most one `receive()` in flight per session, so a flood cannot grow RAM), holds the `PairingGate`, saves the peer on `SavePeer`, replies `pair_abort{busy}` + close within 1 s, and yields when both sides initiate (`pair_with` then returns the replacing responder session's result). Results are `PairingOutcome` (core outcomes plus `unreachable`, `rejected`, `identity_mismatch`, `version_mismatch`, `busy`, `self`, `save_failed`, `prompt_failed`); prompts are `PairingPrompt` (`recent_codes`: codes shown as responder in the current window; `known_name`: the stored name when the peer's `device_id` is already trusted), answered with `decide(session_id, accepted)`; `PairingFinished.code_shown` says whether this session's code reached the user. It loads the `PairingSigner` in `__init__` (may raise `IdentityError`); the responder's verifier is `functools.partial(verify_pairing_proof, peer_cert)`, built only from a validated cert. On a re-pair `_save` updates the name and `paired_at` in both roles. If sending `pair_confirm` fails, `SavePeer` is skipped and the outcome is `connection_lost`. `pair_with` cancelled before the result is settled sends `pair_abort{user}`, cancels any replacing responder session and re-raises `CancelledError`; cancelled after it is settled (`SavePeer` ran: `paired`/`save_failed`, its own or the replacement's) it calls `Task.uncancel()`, reports once and returns the real result. If `on_prompt` raises, the rest of that action batch is dropped and the session is cancelled (responder `pair_abort{busy}`, so `pair_reveal` is never sent; initiator `pair_abort{user}`) with outcome `prompt_failed`, not counted in the per-IP backoff. `on_prompt=None` means the node cannot pair: `accepting=True` or `pair_with` raise `ValueError`.
  - `settings.py`: `Settings.load/save` for `settings.json` (keeps unknown keys; a corrupt file never blocks the app and is copied to `settings.json.bak` before being overwritten). `devices.py`: `parse_manual_address` (`ip[:port]`, IPv4 only), `resolve_trusted` / `resolve_device` (exact name or ≥ 4-char `device_id` prefix; ambiguous → error, never guesses), and `DeviceRegistry`, which merges `trusted.json`, mDNS and connection state into `DeviceView`s (`paired` and the name of a paired device come only from `trusted.json`).
  - Writes to `trusted.json` / `settings.json` run synchronously on the event loop on purpose (small files; RAM state changes together with the file).
  - Clipboard is a feature here, not a layer. It works through a `ClipboardBackend` interface; the UI supplies the Qt version.
- **cli**: `listen` / `pair` run a node in-process (`asyncio.Runner`); `run_listen` / `run_pair(args, lines, out, err)` and `run_list(args, out, err)` are the in-process test seams. mDNS is on when `--host` is the default 0.0.0.0 or with the hidden `--mdns-interface`; `pair <ip>` never uses mDNS, `pair <name>` browses for `_PAIR_BROWSE_TIMEOUT` without advertising or auto-connecting, and a target that looks like an address but is not valid IPv4 is a usage error (2). stdin is read by a daemon thread with `os.read` (never `input()`/`sys.stdin.readline()`, which can cause “Fatal Python error” at shutdown); each line carries its `time.perf_counter()` and lines read before the code was shown are dropped. The pairing prompt (`_prompt_lines`, layout from mvp §7.2) prints a fixed header, then `Mã ghép đôi:   xxx xxx` on its own line, then the peer's claimed name in “…” via `display_name` (and, if `known_name`, one line with the stored name for both roles plus “Ghép đôi xong, tên sẽ đổi thành …” when it differs); nothing the peer chose may come before or on the code line. `run_pair(..., state=_PairState)` records the result before any `await`, so Ctrl+C after pairing still prints the real result and exits 0. `listen` prints a warning right under the code once `PairingPrompt.recent_codes` reaches `WARN_RECENT_CODES`, and keeps waiting after each result (it is also the node until v0.3). Ctrl+Break (SIGBREAK) on Windows is handled like Ctrl+C. Exit codes: 0 ok, 1 runtime error, 2 bad usage. `--json` prints JSON Lines for long-running commands, one object otherwise. Hidden `--host` / `--port` exist only for tests (bind 127.0.0.1, port 0).

Process model: one node per config dir. Up to `v0.2`, each CLI run is its own node and holds `node.lock`. From `v0.3`, the GUI hosts the node and the CLI talks to it over local IPC.

Planned design invariants from the roadmap:
- Transfer works in 1 MiB blocks. Each block frame carries the SHA-256 of its payload in its header (no separate hash batches), and the file is checked with a Merkle root.
- Resume uses a bitfield stored in a `.state` file; a bit is set only after the block matched its hash and was fsynced (every 16 blocks). `resume{seq, bitfield}` is the only resend mechanism and may be sent at any time; each data connection serves exactly one `resume` (`data_open.resume_seq`; `seq` restarts at 1 on every control connection and is never persisted). Every transfer message is idempotent and re-sendable, and each new control connection starts with a resync (`docs/protocol.md` §6.3), so a lost control message never stalls a transfer. Temp files live in `<receive dir>/.teleport/<transfer_id>/`, never next to final names. Before the final rename the receiver re-reads the whole `.part` from disk and re-checks every block. The rename never overwrites: reserve the final name with `O_CREAT | O_EXCL`, then `os.replace` onto that placeholder (works on FAT/exFAT; never a bare POSIX `os.rename`, never `os.link`).
- Backpressure comes from `await writer.drain()` on the sender and a bounded write queue on the receiver, so RAM must not grow with file size.
- All peer input is untrusted. Received filenames must be sanitized (no `..`, no absolute paths, no Windows reserved names), and a received file never overwrites an existing one.

1. `truong-nhom` makes the plan.
2. Run `hoi-lai` on the plan (always for wire, security or user-visible changes; otherwise when the plan has open questions), then ask the user the blocking questions. Write the approved decisions into one spec file and hand that to every later agent.
3. Run `lap-trinh` and `viet-test` in parallel, from the spec's API and done criteria (`giao-dien` instead of `lap-trinh` for `ui`).
4. Loop `soat-code` and fixes until no **nghiêm trọng** or **cao** issues remain. When the change takes input from other machines (`net`, pairing, discovery, receiving files), run `tan-cong` in parallel with `soat-code`; its reproduced findings count the same as review findings. When it may affect an N requirement, run `do-dac` before and after.
5. Re-run ruff and the full pytest after the last fix, then `truong-nhom` gives the verdict, fed with those results and the reports.
6. `tom-tat` writes the CHANGELOG entry, the summary and the commit message.

Run `soat-tai-lieu` before each release and after large doc changes. Commit and push only after the user approves. Small fixes of a few lines can skip the pipeline.

## Conventions

- Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`). Changes users will notice go under `[Unreleased]` in `docs/CHANGELOG.md`.
- The app version lives only in `src/teleport/__init__.py`. The network protocol is versioned separately, in `docs/protocol.md`.
- The project is licensed GPL-3.0-or-later. Runtime or bundled dependencies must be GPLv3-compatible: MIT/BSD/Apache-2.0/LGPL. The one exception is PyInstaller (GPL with a bootloader exception); package with `--onedir` so users can replace the LGPL libraries. Dev-only tools may use other licenses: `hypothesis` (MPL-2.0) is approved.
